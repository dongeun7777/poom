# 솜구름 — 홈페이지 프로토타입

아기옷부터 가족옷까지, 소재를 축으로 한 브랜드 **솜구름** 의 프리런치 사이트.
빌드 도구 없이 정적 파일만 씁니다. `index.html`을 더블클릭하면 바로 열립니다.

## 열기

파일 탐색기에서 `index.html` 더블클릭. 또는 로컬 서버로:

```powershell
py -3 -m http.server 5173      # Python
npx --yes serve -l 5173        # Node
```

→ http://localhost:5173

## 파일

```
poom/
├─ index.html        홈 — 히어로 → 라인 4종 → 13 사이즈 → 더 알아보기 → 대기자
├─ products.html     라인 — 4개 카드 + 가격 사다리
├─ product.html      제품 상세 — ?id= 로 품목 전환
├─ fabric.html       원단 — 조직 비교, 라인별 추천, 뺀 원단과 이유
├─ care.html         얼룩과 세탁 — 상충 설명, 응급처치, 얼룩별 대응
├─ about.html        About us — 시작한 이유, 세 가지 규격, 못 하는 것
├─ label.html        목 뒤 라벨
└─ assets/
   ├─ style.css      전체 스타일 (토큰 → 컴포넌트 순)
   └─ site.js        SVG 스프라이트 + 카탈로그 + 장바구니 + 대기자
```

제품 상세는 쿼리스트링으로 갈립니다:

- `product.html?id=sleep-set` — 슬립 세트 (첫 생산 품목)
- `product.html?id=base-inner` — 이너 · 보디수트
- `product.html?id=play-smock` — 식사 스목 (얼룩 대응 라인)
- `product.html?id=knit-out` — 니트 아우터

## 사진 넣기 (중요)

옷 그림은 전부 **SVG 일러스트**입니다 (`assets/site.js` 맨 위 `SPRITE`).
실사진이 생기면 `assets/img/` 에 아래 이름으로 넣기만 하면 **그림 대신 사진이 자동으로 뜹니다.**
파일이 없으면 조용히 일러스트가 남습니다 — 지금이 그 상태입니다.

```
assets/img/
  sleep-set-1.jpg ~ -4   슬립 세트 (1번이 대표, 2~4는 썸네일)
  base-inner-1.jpg ~
  play-smock-1.jpg ~
  knit-out-1.jpg ~
  one-fabric.jpg  fabric.jpg  stain.jpg  care-card.jpg
```

권장 비율: 대표 4:3, 썸네일 1:1, 카드 4:5.

## 동작하는 것 / 안 하는 것

**동작합니다**

- 사이즈 선택 (50cm–XL 11개) — 사이즈 그룹에 따라 가격이 바뀝니다
- 컬러 스와치 — 누르면 옷 그림 색이 바뀝니다 (목록 카드에서도)
- 수량 조절, 장바구니 담기, 카트 드로어, 항목 삭제, 배송비 포함 합계
- 모바일 하단 고정 구매 바
- 오픈 알림 신청 + 대기자 수 카운터
- 다크/라이트 자동 전환, 모바일 반응형

**안 합니다** — 프로토타입이라 일부러 비워둔 부분

- 결제, 배송, 회원, 재고
- 서버 저장. 장바구니(`poom.cart.v1`)와 대기자(`poom.waitlist.v1`)는
  **브라우저 localStorage**에만 남습니다.

대기자 명단을 꺼내려면 콘솔(F12)에서:

```js
JSON.parse(localStorage.getItem('poom.waitlist.v1'))
```

홈에 남긴 건 각 주제당 한 줄 + 링크 카드입니다. 브랜드의 유일한 차별점이
"규격을 지킨다"는 주장이라 완전히 빼지는 않았습니다.

## 상점처럼 보이게 (2026-09-09, 2차)

"블로그 같다"는 지적을 받고 코니(konny.kr / konnybaby.com)를 확인했습니다.
문제는 캐러셀이 없어서가 아니라 **읽는 페이지 문법**을 쓰고 있어서였습니다 —
좌측 정렬 긴 문단, 여백 큰 잡지 레이아웃, 제품 블록이 페이지 전체에 하나.
코니는 제품 줄이 여섯 개입니다.

얹은 상거래 문법:

| 요소 | 코니 | 솜구름 |
|---|---|---|
| 공지 바 | 프로모션 2줄 | 사실 3줄 회전 (`initNotice`) |
| 히어로 | 4장 캐러셀 | 3장 캐러셀 (`initShowcase`) |
| 제품 줄 | 6개 | 라인 4종 + 컬러 + 사이즈 = 3줄 |
| 카드 상태 | `일시품절 9/16 11:00` | `첫 생산 · 대기 접수 중` / `2차 생산 예정` |
| 브랜드 서사 | 배너 + About Us | 배너(`.bband`) + `about.html` |

**할인·품절·리뷰수는 만들지 않습니다.** 아직 판 적이 없어서 전부 거짓말이 됩니다.
카드 상태 줄에는 사실만 씁니다.

내비게이션은 코니와 같은 순서 — 제품 카테고리 먼저, About us 마지막.
`기준` 이라는 이름이 제품 카테고리처럼 읽혀서 `About us` 로 바꿨습니다
(`standard.html` → `about.html`).

캐러셀은 6.5초 자동, 마우스·포커스 올리면 정지, 직접 넘기면 9초 쉬었다 재개,
좌우 화살표·점·키보드·스와이프 지원. `prefers-reduced-motion` 이면 자동 넘김 없음.
꺼진 슬라이드는 `hidden` 이라 낭독기와 탭 이동이 건너뜁니다.


## 상점 흉내를 걷어냄 (2026-09-09, 3차)

2차에서 코니 문법을 그대로 얹었다가 더 엉성해졌습니다.
**SKU 40개짜리 상점의 문법을 SKU 4개짜리 브랜드에 씌운 것**이 원인입니다.

걷어낸 것과 이유:

| 뺀 것 | 왜 |
|---|---|
| 3장 캐러셀 | 할 말이 하나. 메시지의 2/3을 타이머 뒤에 숨김 |
| 공지 바 3줄 회전 | 바로 아래 신뢰 줄과 같은 내용 |
| 컬러/사이즈로 고르기 | `?color=` `?size=` 가 아무것도 안 거름 (죽은 링크) |
| `5만원 이상 무료배송 · 14일 교환` | 배송 정책도 교환 정책도 없음 |
| 카드 4장 + `2차 생산 예정` | 진열대의 75%가 안 팔림 |

대신 넣은 것:

- 히어로는 **배너 한 장** (`.banner`) — 전면 2단, 캐러셀 아님
- **첫 생산 한 품목을 크게** (`.feature`) — 아기 슬립수트 + 성인 슬립 상의
- 사이즈 사다리에서 **첫 생산 5개만 채운 칩** (`.sizechip.on`), 나머지는 전개 계획
- 「다음에 만들 것」은 카드가 아니라 **목록** (`.soon`) — 못 사는 것에 카드를 주면 파는 척이 됨
- 가격 옆 **`예상가`** 표기 (`.price em`) — 견적 전 숫자라는 걸 값에서 떼지 않음
- 전 페이지 공지 바: **"아직 팔지 않습니다"**

**원칙: 없는 것은 만들지 않습니다.** 할인·품절·리뷰수·배송정책은 전부
아직 사실이 아니라서 쓰지 않습니다. 상점처럼 보이는 것보다
"만들기 전인 브랜드"로 정확히 보이는 쪽이 낫습니다.


## 뒤집어 입어도 되는 옷 (2026-09-09)

코니 분석에서 나온 문제: **코니의 차별점은 사진에 찍히지만, 우리 것은 안 찍힙니다.**
크림색 슬립수트 사진은 다른 크림색 슬립수트 사진과 똑같습니다.
택 없음·눕힌 솔기·Class I 은 전부 보이지 않습니다.

그래서 규격의 **결과**를 문장으로 뽑았습니다.

> **뒤집어 입어도 되는 옷.**
> 목 뒤에 택이 없고 시접을 눕혀 박으면, 안과 밖이 같아집니다.

이게 좋은 이유:

- 한 문장으로 설명됨
- **사진으로 증명됨** — 겉과 안을 나란히 놓으면 구분이 안 됨
- 손님이 **집에서 직접 확인** 가능
- 따라 하려면 택을 떼고 봉제 설비를 바꿔야 함

파일:

```
assets/img/reversible.svg              사이트용 (문장 없음, CSS 변수로 색 제어)
production/flats/reversible-captioned.svg   문장 포함
production/flats/reversible.png        1200x627 — 공유·발주용
```

`reversible.svg` 는 `--rv-cloth` `--rv-line` `--rv-accent` `--rv-ink` `--rv-ash`
를 받습니다. `.rvfig img` 에서 테마 토큰을 물려주므로 다크 모드에서도 따라옵니다.

**주의: 아직 확인 안 된 주장입니다.** 시접 처리가 실제로 그 수준인지가 전제입니다.
사이트에 *"첫 샘플을 받아 직접 뒤집어 입혀 본 뒤에 확정합니다. 안 되면 이 문장을 내립니다"*
라고 적어 뒀습니다. 샘플에서 안 되면 **반드시 내려야 합니다.**


## 표식은 솔기입니다 (2026-09-09)

겉에 로고를 안 박기로 한 브랜드가 어떻게 알아보이게 할 것인가.
답: **눕힌 솔기를 한 톤 어두운 오트색 실(`#C8B48F`)로 박습니다.**

`--thread` 토큰과 `.figure .seam` 으로 전 페이지 옷 그림에 반영돼 있습니다.
`assets/img/seam-mark.svg` 가 지금 / 오트색 비교, `about.html#mark` 가 그 설명입니다.

### 같이 정정한 것 두 가지

**1. 아기 제품 그림이 틀려 있었습니다.**
첫 생산은 **긴팔·긴바지 원피스형 슬립수트**인데 사이트는 짧은 `g-bodysuit` 을 쓰고 있었습니다.
`production/flats/baby-sleepsuit-front.svg` 와 같은 형태로 `g-sleepsuit` 심볼을 새로 넣었습니다
(원본 210x300 을 0.8 로 줄여 200x240 에 맞춤). `g-bodysuit` 은 Base 라인 전용으로 남깁니다.

**2. `슬립 세트` 는 사실이 아니었습니다.**
카탈로그 설명이 *"사계절 상하 세트"* 였는데 첫 생산에 하의가 없습니다.
`슬립웨어` 로 바꾸고, **몸에 따라 형태가 달라진다**로 정리했습니다 —
아기는 원피스형(신생아는 위아래 따로 잘 안 입힙니다), 어른은 상의.

**3. `구분되지 않습니다` 도 더는 참이 아닙니다.**
눕힌 솔기는 양면의 실 무늬가 다릅니다(사다리 / 사슬). 오트색 실을 쓰면 그게 보입니다.
`어느 쪽으로 입어도 됩니다` 로 바꿨습니다 — 양쪽 다 평평하고 택이 없다는 건 그대로 참입니다.
`label.html` 의 *"겉에서는 아무것도 보이지 않습니다"* 도 같이 고쳤습니다.


## 구름과 무게 (2026-09-09)

### 헤더에 구름 마크

`.mark .cloud` — 구름 윤곽을 **옷 솔기와 같은 오트색 실**(`--thread`)로 박은 형태.
같은 `stroke-dasharray` 를 씁니다. 로고와 옷의 표식이 같은 언어입니다.
파비콘도 같은 구름으로 교체했습니다.

옷에도 옮길 수 있습니다 — 밑단 옆선에 같은 실로 한 번 박으면
피부에 닿지 않는 자리에 표식이 생깁니다.

### 무게 뺀 곳 다섯

"아기옷 파는 사이트치곤 너무 묵직하다"는 지적. 구조는 그대로 두고 색과 두께만 바꿨습니다.

| 무엇 | 전 | 후 |
|---|---|---|
| 공지 바 | 새까만 띠 (열자마자 검정) | 오트색 바탕 |
| 제목 | 자간 −.035em, h1 68px | 자간 −.028em, h1 60px, 행간 여유 |
| 버튼 | 새까만 알약 | 데님 (`--accent`) |
| 장바구니 | 검정 알약 | 테두리만 |
| 얼룩 섹션 | 네이비 큰 덩어리 | 미스트 (연한 하늘) |

`.panel.deep` 이 더는 어둡지 않으므로 어두움을 전제하던 규칙
(`.tocard`, `.steps`, `.sizechip`, `.deeplink`)을 전부 걷어냈습니다.
**`.panel.deep` 안에 뭘 추가할 때 `--on-accent` 를 쓰지 마세요.**

### 히어로 하늘

평평한 베이지 덩어리가 무거움의 큰 원인이었습니다.
`radial-gradient` 4겹 + `.sky` (feGaussianBlur 34 먹인 타원 5개, opacity .40).
**형태가 또렷하면 클립아트가 됩니다** — 흐릿한 대기 수준으로만 유지할 것.
다크 모드에서는 opacity .16.

`.btext` 는 바탕을 깔지 않고, `.bmedia` 는 틴트를 62% 로 섞어 하늘이 이어지게 했습니다.


### 헤더 하늘 (히어로 아님)

**하늘은 맨 위 띠와 내비게이션에만.** 히어로는 크림/오트 두 톤 그대로입니다.

```css
--sky-top:#C2D7E4   /* 공지 바 · 내비 위쪽 */
--sky-bot:#E2ECF2   /* 내비 아래쪽 */
--cloud:#FAFCFD     /* 뭉게구름 — 순백이 아니라 아이보리 */
```

`.navsky` 는 각 페이지 `<header class="nav">` 안 인라인 SVG.
구름은 원 4개 + 둥근 사각형으로 만든 `#cu` 를 세 번 씁니다.

### 여기서 배운 것 — 세 번 틀렸습니다

1. **구름을 `--card`(#FFFCF7)로 칠함.** 바탕 `--cream`(#F7F3EC)과 거의 같은 색이라
   아무것도 안 보였습니다. 흰 구름을 쓰려면 **바탕이 하늘색**이어야 합니다.
2. **히어로에 깔았음.** 요청은 헤더였습니다.
3. **순백 구름 6개 + 진한 파랑.** 유아용품몰 배너처럼 유치해졌습니다.

**세 번째가 핵심입니다.** 구름 자체가 유치한 게 아니라 **대비와 개수**가 문제였습니다.

| | 유치함 | 차분함 |
|---|---|---|
| 구름 색 | 순백 #FFFFFF | 아이보리 #FAFCFD |
| 하늘 | #A9C9E0 (진한 파랑) | #C2D7E4 |
| 개수 | 6개 균등 배치 | 3개 |
| 크기 | 작게 여러 개 | 크게, 아래로 잘려 지평선처럼 |
| 블러 | 1.6 | 3.2 |

**구름을 더/덜 하려면 이 표의 다섯 값만 움직이면 됩니다.**


## 팔레트 — 하늘 하나로 만든 명도 계단 (2026-09-09)

헤더가 하늘인데 아래가 베이지라 안 붙었습니다.
**회색으로 식히기만 하면 여전히 따로 놉니다** — 헤더만 파랗고 본문은 무채색이니까요.
같은 색상(약 203도)에서 밝기만 다르게 잡아 전부 한 집안으로 묶었습니다.

```
sky-1  #C2D7E4   공지 바 · 헤더 위      (--sky-top)
sky-2  #DDE9F0   헤더 아래              (--sky-bot)
       #D8E5EE   히어로 그림 칸         (--mist, UI 틴트)
sky-3  #E9F1F6   패널                   (--sand)
sky-4  #F4F8FA   바탕                   (--cream)
sky-5  #FBFDFE   카드                   (--card)
```

글자·선도 같은 색상 계열: `--ink:#1F2A31` `--ink2:#4E5C65` `--ash:#7E8B93`
`--line:#DCE6EC` `--line2:#C0D0DA`. 그림자도 `rgba(31,42,49,...)`.

**안 바꾼 것 — 따뜻한 색은 여기만:**

| | 어디 |
|---|---|
| `--thread` `#C8B48F` | 옷 솔기 · 헤더 구름 로고 |
| `--oat` `--clay` `--sage` | 제품 라인 색 (실제 원단 색) |
| 옷 그림 채움 `#F6F1E8` | 크림 원단 |

**서늘한 세계에 따뜻한 실 한 줄** — 브랜드 표식이 색으로도 읽힙니다.
새 색을 넣을 때 이 규칙을 깨지 마세요. 따뜻한 색은 원단과 실 자리에만.
